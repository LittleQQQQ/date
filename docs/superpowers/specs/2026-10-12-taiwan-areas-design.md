# 可選地區擴大到全台：設計規格

日期：2026-10-12

## 目標

可選的商圈從六都 7 個擴大到全台 20 個縣市，每個有影城的縣市 1 個商圈，繞著該縣市的主要影城。商圈、車站、交通路網延續手寫估計值（`data/fixture/`），格式不變，以後換成 TDX 真實時刻時不用改排程。

## 已確定的決定

| 項目 | 決定 |
|---|---|
| 交通資料 | 先手寫估計值，之後再接 TDX |
| 商圈數量 | 每個有影城的縣市 1 個，繞著主要影城；離商圈車站步行超過 15 分鐘的影城這次不涵蓋 |
| 離島 | 澎湖、金門納入，只能從島上出發 |
| 高雄 | 「巨蛋」附近沒有影城，改成「三多」 |
| 沒有商圈的縣市 | 嘉義縣（沒有影城；高鐵嘉義仍可當出發站）、連江縣（開眼沒有資料） |

## 爬蟲工作量

- 開眼：地區頁從 5 個變 18 個；第一次約 20 分鐘（多了約 30 張地圖頁、約 25 家影城 × 4 天的時刻表、新片的電影頁），之後每天多 2～3 分鐘。
- OSM：商圈從 7 個變 21 個；每次約 10～20 分鐘，視 Overpass 忙碌程度。

## 升級後的一次性動作

資料表結構不變，不需要 `--reset`。伺服器重新啟動時 `base` 會匯入新商圈與路網，但自動更新判斷「今天已經抓過開眼、OSM 本週已成功」，新縣市的影城要隔天、餐廳要 7 天後才會補上。README 寫明升級後依序手動執行（先停伺服器）：

    python -m app.ingest
    python -m app.ingest --source atmovies
    python -m app.ingest --source osm

最後再啟動伺服器。

不做自動判斷：「某商圈還沒有資料」無法和「這個商圈本來就抓不到」區分，會造成每天重抓。

## 不做的事

- TDX 真實時刻（之後再接）。
- 每縣市第二個商圈、涵蓋所有影城。
- 本島與離島之間的交通（飛機、船）。
- 自動偵測「新增商圈需要補抓」。
